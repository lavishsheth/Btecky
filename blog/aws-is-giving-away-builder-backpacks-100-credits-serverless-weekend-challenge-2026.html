What Is the AWS Weekend Challenge: No Pipeline, No Problem?

The Weekend Challenge: No Pipeline, No Problem is a project-building challenge hosted on AWS Builder Center.

The theme is serverless development.

AWS wants participants to demonstrate how useful applications can be built using managed cloud services without the burden of maintaining servers or deployment infrastructure.

The challenge encourages developers to focus on the actual problem they want to solve instead of spending time managing infrastructure.

You bring an idea, choose suitable serverless AWS services, connect them together, and submit a working project.

The challenge description specifically highlights these AWS services:

  • AWS Lambda: Run application code without managing servers.
  • Amazon API Gateway: Create and manage application endpoints.
  • Amazon DynamoDB: Store and retrieve application data.
  • Amazon S3: Store files and other application objects.
  • AWS Step Functions: Coordinate workflows across different services.

You do not necessarily need to use every service listed. Your project must include at least one serverless AWS service and meet the challenge's other submission requirements.

The main objective is simple: build something real, demonstrate that it works, and explain how your serverless architecture solves a problem.

AWS Services You Can Use

The challenge description highlights five important serverless AWS services.

1. AWS Lambda

AWS Lambda is a serverless compute service that allows you to execute code without managing servers.

You can use Lambda functions to:

  • Process incoming requests.
  • Validate user input.
  • Execute business logic.
  • Process uploaded files.
  • Trigger automated operations.
  • Connect different AWS services.

For example, in a serverless image-processing application, a Lambda function could automatically process an image after it is uploaded to an S3 bucket.

2. Amazon API Gateway

Amazon API Gateway helps developers create and manage APIs.

You can use it to expose endpoints that allow frontend applications or other systems to communicate with your backend.

For example, an expense tracker could use API Gateway to provide endpoints for adding, updating, and retrieving expenses.

3. Amazon DynamoDB

Amazon DynamoDB is a managed NoSQL database service.

It can store application data such as:

  • User information.
  • Task records.
  • Transaction details.
  • Application settings.
  • Processing status.

For a serverless application, DynamoDB can provide a scalable data storage layer without requiring you to manage database servers.

4. Amazon S3

Amazon Simple Storage Service (Amazon S3) is an object storage service.

It can be used to store:

  • Images.
  • Documents.
  • Reports.
  • Uploaded files.
  • Generated application output.

For example, you could build a document-processing application where users upload files to S3 and Lambda automatically processes them.

5. AWS Step Functions

AWS Step Functions helps coordinate multiple steps in an application workflow.

You can use it when a task requires multiple operations to run in a particular sequence.

For example, an automated document-processing workflow might:

  1. Receive a document.
  2. Validate the uploaded file.
  3. Process its contents.
  4. Store the output.
  5. Update the processing status.

Step Functions can help coordinate such workflows across AWS services.

Remember: The challenge requires at least one serverless AWS service as part of your build. You do not have to use all five services.

Project Submission Requirements

This is one of the most important sections. Before submitting, make sure your project meets the requirements mentioned on the official challenge page.

Your submission must include the following:

1. Submit a Previously Unpublished Project

Your entry must be a previously unpublished project.

Choose a fresh idea and build a solution specifically for the challenge.

2. Explain the Problem You Are Solving

Clearly describe:

  • What problem did you identify?
  • Who experiences this problem?
  • Why is it worth solving?
  • How does your project help?

Do not just explain the technologies you used. The judges should understand the actual problem your application addresses.

3. Explain Your Serverless AWS Architecture

Mention the AWS services used in your project and explain how they connect.

For example:

  • API Gateway receives application requests.
  • Lambda executes the business logic.
  • DynamoDB stores application data.
  • S3 stores uploaded files.
  • Step Functions coordinates multi-step workflows.

You should include an architecture diagram if possible.

A simple diagram can make it much easier for judges to understand how your application works.

4. Include at Least One Serverless AWS Service

Your build must include at least one serverless AWS service.

The challenge also emphasizes that participants should not have servers or deployment pipelines to manage.

Make sure your project follows the serverless requirement rather than simply using AWS as a hosting platform.

5. Add a Public Demo Video

This is a mandatory submission requirement.

In the Demo field of your project submission, include a link to a short public video.

The video must:

  • Be less than 3 minutes long.
  • Be publicly accessible.
  • Show your project running.
  • Demonstrate the application end to end.

You can use platforms such as YouTube, Vimeo, or Facebook to host your demo.

Important: Do not forget the demo video. A project without the required public demo link may fail the entry requirements.

How Will AWS Select the Winners?

The challenge follows a two-gate evaluation process.

This means entries are first checked and scored before the final judges select the 10 winners.

Gate 1: AI Scoring and Human Review

Every submission is first checked against the entry requirements.

After this initial check, entries are evaluated using a combination of AI scoring and human review.

The 50 highest-scoring entries advance to the second gate.

Gate 2: Judge Review

A panel of AWS judges reviews the top 50 projects.

The judges then select the 10 winners using the same four evaluation criteria and weight distribution.

Evaluation Criteria and Weightage

Let's understand what each criterion means.

1. Technical Innovation and Originality – 25%

Judges evaluate how clever and original your idea is and how effectively you use serverless AWS services.

Try to avoid simply copying a common tutorial project. Identify a problem and demonstrate your own approach to solving it.

2. Craft and Execution – 25%

Your project should work reliably.

The judges will consider how well your AWS services fit together and how effectively the complete application runs.

A small working application is better than a complicated project that does not function properly.

3. Usefulness and Impact – 25%

Your project should solve a meaningful problem.

Think about whether other people could benefit from your solution and whether the architecture or implementation could be reused.

4. Creativity and Storytelling – 25%

Your project explanation and demo video should clearly communicate what you built.

Explain the problem, demonstrate the solution, and show how the different AWS services work together.

A good technical project deserves a good presentation.

Tips to Improve Your Chances of Winning

AWS has also shared useful suggestions for participants.

Here are some practical ways to make your submission stronger.

1. Keep Your Project Scope Small

Do not try to build a massive application in one weekend.

Choose one specific problem and focus on solving it properly.

A small application that works from beginning to end can make a stronger submission than a large unfinished project.

2. Create an Architecture Diagram

Your architecture diagram should show how requests and data move between AWS services.

For example:

User → API Gateway → Lambda → DynamoDB

You can extend the architecture using S3 and Step Functions if your project requires them.

Keep the diagram simple and easy to understand.

3. Demonstrate Serverless Benefits

The challenge specifically highlights the benefits of serverless architecture.

Show how your project can operate without maintaining traditional servers or managing capacity.

AWS also suggests highlighting applications that scale to zero when idle and have very low idle costs.

4. Mention the Tools You Used

If you used any of the following tools, explain how they helped you build your project:

  • AWS SAM.
  • AWS Cloud Development Kit (AWS CDK).
  • AWS Step Functions Workflow Studio.

The challenge specifically encourages participants to call out how they used these tools so other developers can reuse the pattern.

5. Make Your Demo Video Clear

Your video should be short and demonstrate the application working end to end.

A useful structure is:

  • First 15–20 seconds: Introduce the problem.
  • Next 30–40 seconds: Explain your solution.
  • Next 60–90 seconds: Demonstrate the working application.
  • Final 20–30 seconds: Explain the AWS architecture and services used.

Keep the video under three minutes, as required by the challenge.
